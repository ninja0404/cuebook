## 1. 产品概述

### 1.1 是什么

CueBook 是一个**交易前（pre-trade）的认知网络**。它不是交易所、不是荐股工具、不是新闻聚合器。它服务于交易**发生之前**那段最关键、却最缺乏好工具的认知过程：

> 一个新的金融叙事出现了 → 它是什么？为什么有人在买？哪里可能被过度解读？我怎么看？我的判断对不对？

CueBook 用三个一级动作覆盖这段过程，全部围绕一个中枢对象 **Narrative Room** 展开：

- **`/bet`** — 发现叙事。AI 持续供给有来源、可解释、值得追的叙事卡。
- **`/frame`** — 表达观点。把观点、证据、资产线索、交易想法做成可传播的内容单位。
- **`/trade`** — 验证判断。用低压力模拟仓位检验自己的判断，而非实盘下单。

最终，每一次判断的结果（价格、事件、时间窗）回流为**结算记忆**，累积成用户的认知信誉，并让下一次的叙事排序更可信。

### 1.2 电梯演讲

> 信息以碎片形式爆炸（X、群聊、新闻），但**理解**是稀缺的。ChatGPT 能解释单点，却没有持续状态和多人信号；交易所能执行，却不告诉你"为什么现在该关注这条叙事"。CueBook 把**发现、理解、表达、验证、回流**串成一条链，让任何人在下任何注之前，先拿到那个 **Cue**。

### 1.3 产品边界（明确不做什么）

| 不做 | 原因 |
|---|---|
| 实盘下单 / 撮合 / 托管资金 | `/trade` 是认知验证工具，不是经纪业务。规避牌照与资金风险。 |
| 直接荐股 / "买入"信号 | 平台供给的是**有来源的叙事 + 反方 + 验证点**，不是投资建议（见 §8 合规）。 |
| 通用新闻聚合 | 只供给"有清晰判断、有来源、有资产机制"的叙事，质量门槛优先于数量。 |
| 社交泛内容（散帖） | 每个 Frame 必须挂到叙事 / 资产 / 证据 / 验证点，否则不进入可见层。 |

## 2. 问题陈述与机会

### 2.1 核心问题

**新叙事出现得比理解更快。** 用户缺的不是信息，而是一条**持续更新的叙事线**：证据、分歧、资产映射、市场反馈、可验证的交易语境——并且能看到别人的判断在同一对象上沉淀。

现状的四类工具各自缺位：

| 角色 | 代表 | 缺什么 |
|---|---|---|
| 信息入口 | X / KOL / 新闻 / 群聊 | 快，但碎片化，真假难辨、优先级不明 |
| 解释工具 | ChatGPT / 搜索 | 能解释单点，但缺**持续状态**和**多人信号** |
| 交易场所 | Broker / CEX / DEX | 能执行，但不解释"为什么现在该关注这条叙事" |
| **认知网络** | **CueBook** | Markets、/bet、Room、/frame、/trade、Portfolio 与记忆**在一条链上** |

### 2.2 为什么是现在

- **AI 能力**：LLM 已能把碎片事件综合成有来源、有资产机制、有反方的结构化叙事——这是 `/bet` 自动供给的前提，解决了内容冷启动。
- **市场结构**：Crypto 市场本身就是**叙事驱动**、7×24 结算、行情实时免费，与"交易前认知"的命题天然契合，是最佳切入点。
- **跨资产传导**：crypto / tokenized stocks / AI capex / macro 互相传导，用户需要把一个事件快速映射到多个资产和二阶影响——没有工具在做这件事。

## 3. 目标用户

### 3.1 三类画像

**P-A｜美股资深交易者（跨界 crypto）**
- 遇到：HYPE、perps、on-chain venue 等新物种。
- 痛点：从零补 crypto 语境，容易只看到情绪化推荐。
- 想要：1 分钟知道——它是什么、为什么有人买、哪里可能被过度解读。

**P-B｜Crypto native（跨界股票 / 宏观）**
- 遇到：tokenized stocks、AI capex、macro。
- 痛点：懂币，但不一定懂股票、监管和宏观传导。
- 想要：快速把事件映射到资产和二阶影响。

**P-C｜普通交易用户（被叙事卷入）**
- 遇到：朋友分享的热点叙事。
- 痛点：X / 群聊 / 新闻碎片太多，难判断真假和优先级。
- 想要：看到证据、反方、下一步验证点，再决定是否关注。

### 3.2 MVP 用户优先级（推荐，见 §11-D）

> **首发优先 P-B（Crypto native）+ P-A 中对 crypto 好奇的部分**，因为 MVP 首发标的为 Crypto。
> **P-C 通过"被分享的 Frame / Room"进入**——这是产品的病毒/分享入口，不是首发主动获取的对象，但分享体验必须从第一天就打磨好（落地即 1 分钟看懂）。

## 4. 核心概念模型

> 这是全产品的"名词表"与关系骨架。所有功能、数据模型、API 都应与此一致。

### 4.1 实体与定义

| 实体 | 定义 | 一句话职责 |
|---|---|---|
| **Narrative Room** | 一个可分享 / 可理解 / 可追踪 / 可创作 / 可连接 / 可验证的**市场认知对象**。 | **中枢**。所有动作的聚合点，下面所有实体都挂在它上面。 |
| **Cue（叙事卡 / Narrative）** | AI 生成的、有来源的叙事入口卡。`/bet` 的可见单位。 | 发现与进入 Room 的入口。 |
| **Frame** | 用户创作的观点内容单位（观点 + 图表 + 证据 + 链接）。 | 表达与传播；带 context 出去，把流量带回 Room。 |
| **Trade（Paper Trade）** | 一次低压力模拟验证（方向 + 失效点 + 时间窗）。 | 把"看懂了"推进到"愿意验证"，产出可结算样本。 |
| **Asset** | 跨类别的标的（symbol + 类别 + venue）。类别：crypto / stock / macro。 | 叙事与传导图的连接锚点。 |
| **Evidence / Source** | 支撑判断的来源（官方 / 二级 / 链上）。 | 信任底座，每条可见判断必须可溯源。 |
| **Settlement** | 对一个 Trade 的不可变结算记录（价格 / 事件 / 时间窗判定）。 | 把判断变成可累积的认知记忆。 |
| **Reputation** | 用户基于结算样本累积的认知信誉（多维）。 | 影响叙事 / Frame 排序与可信度。 |

### 4.2 关系（以 Room 为根）

```
Narrative Room (1)
├── (1..*) Cue            AI 供给的叙事卡（一个 Room 可由一张 Cue 开启，可累积多张）
├── (0..*) Frame          用户观点，挂在 Room 上
├── (0..*) Trade          模拟验证，挂在 Room 上，可被 Frame 引用
├── (1..*) Asset          Room 关联的资产与二阶传导图
├── (1..*) Evidence       来源与反方证据
└── (derived) Signals     判断聚合（站队 / 时间窗 / 风险）→ 热度与排序

Frame (1) ── links ──> (0..1) Trade        Frame 可链接一个模拟交易
Trade (1) ── produces ─> (1) Settlement     到期 / 触发后产生不可变结算
Settlement (*) ── rolls up ─> Reputation     结算样本累积为信誉
```

### 4.3 关键状态机

**Narrative Room 热度态**（用于排序与展示，源自 deck 的 Emerging/Moving/Leading）：
```
Emerging（最新有来源的 AI 叙事）
  → Moving（价格已开始响应）
  → Leading（用户 Frame / 模拟收益领先）
  → Fading（注意力与验证流枯竭）
```

**Cue 生命周期**（AI 供给管道，见 §7.1）：
```
candidate（AI 草拟）→ vetted（过质量门槛：判断 + 来源 + 资产机制）
  → published（进入可见层 + 开/并入 Room）→ archived
失败分支：candidate → rejected（未过门槛，不可见）
```

**Trade（Paper）生命周期**：
```
open（已建立：方向 + 失效点 + 时间窗）
  → active（持续追踪价格与失效条件）
  → settled：命中目标 | 触发失效点 | 时间窗到期
（settled 即写入不可变 Settlement，回流 Reputation）
```

**Frame 生命周期**：
```
draft → published →（可选）linked（关联 Trade / Asset / 其他 Room）
published 后持续累积传播与结算信号 → 计入信誉与排序
```

## 5. 核心用户旅程

### 5.1 主闭环

```
发现 ──→ 理解 ──→ 表达 ──→ 验证 ──→ 回流
/bet    Room     /frame   /trade   结算记忆 / 信誉 / 排序
                                        └────────┘
                                   回流让下一次"发现"更可信
```

### 5.2 入口路径

```
/markets → /bet → Narrative Room → /frame 或 /trade → /portfolio
（任意资产或叙事进入；分享链接可直达某个 Room）
```

### 5.3 关键场景叙事（分享驱动，服务 P-C）

> 朋友分享一个关于 HYPE / perps 的 **Frame** 链接 → 用户点开，进入**同一个 Narrative Room** → 先看 AI 的 1 分钟摘要（核心判断、证据、资产机制、下一步验证点）→ 然后三选一：**追**这个资产 / Room、发自己的 **Frame**、做一次模拟 **Trade**。
>
> 网络效应正源于此：同一个叙事对象不断变厚——事实来源、用户 Frame、结构化判断、资产连接、模拟验证、结算记忆，全部沉淀在一起。

## 6. 功能需求（按 Epic）

> 优先级：**P0** = MVP 闭环必须；**P1** = 闭环增强；**P2** = 后续 / 规模化阶段。
> 每个 Epic 含：目标 / 关键用户故事 / 需求清单 / 关键验收标准。

### E1 — Markets + /bet 叙事发现

**目标**：让用户快速发现最新、可解释、值得追的市场叙事，且不依赖用户先发内容。

**用户故事**
- 作为 P-B，我想在 `/bet` 看到最新的、有来源的叙事卡，以便快速发现值得研究的市场故事。
- 作为 P-A，我想按资产 / 类别浏览叙事，以便从我关心的标的切入。

**需求**
- `/bet` 叙事流：最新（Newest）/ 热门（Trending）两种排序。**P0**
- 叙事卡（Cue）展示：类别标签、一句话判断、关联资产、来源状态。**P0**
- `/markets`：按资产浏览，资产详情聚合其关联 Room / Cue。**P0**
- 叙事搜索（按资产 / 关键词 / 叙事）。**P1**
- 质量门槛过滤：只有过门槛的 Cue 进入可见层（见 §7.1）。**P0**
- 卡片点击 → 进入对应 Narrative Room（卡片不是终点）。**P0**

**关键验收**
- 每张可见 Cue 都有：清晰判断 + 至少一个来源 + 至少一个关联资产。
- 点击任意 Cue 必落入一个 Room，且 Room 已有 AI 摘要。

### E2 — Narrative Room（1 分钟理解）

**目标**：让用户进入 Room 后 1 分钟内看懂"为什么这条叙事在动"。

**用户故事**
- 作为任意用户，我想在进入 Room 后立刻看到核心判断、证据、资产影响和下一步验证点，以便快速决定是否继续投入。

**需求**
- Room 头部 AI 摘要：核心判断（bottom line）、时间线、资产传导、**容易被过度解读的地方**、下一步验证点。**P0**
- 证据区：来源列表（官方 / 二级 / 链上）+ 反方证据。**P0**
- 资产传导图：关联资产 + 二阶影响（什么变量变化 → 为什么影响定价）。**P0（可先轻量列表，P1 升级为图）**
- Room 内动作区：Watch（追踪）/ 发 Frame / 做 Trade 的入口。**P0**
- 判断聚合（Signals）：站队（看多 / 看空 / 不确定）、时间窗、风险的可视化聚合。**P1**
- 讨论提示（discussion prompts）：引导用户表达的结构化话题。**P1**

**关键验收**
- 摘要必须包含"容易被过度解读的地方"——这是与情绪化推荐的核心区隔。
- 首屏（含摘要）在分享落地场景下可被陌生人无背景读懂。

### E3 — /frame 创作与连接

**目标**：让用户把观点做成可传播、可排序、可结算的内容单位，并把外部流量导回 Room。

**用户故事**
- 作为有观点的用户，我想发布一个挂着证据和交易想法的 Frame，以便表达判断并被纳入排序与结算。

**需求（Frame Studio）**
- **Post**：发短观点 / 图表 / 截图 / 反方证据。**P0**
- **Link trade**：链接一个模拟 Trade / 持仓想法 / 入场条件 / 失效点。**P0**
- **Connect**：连接资产、其他 Narrative Room、验证点。**P0**
- **Spread**：分享 Frame 或完整 Room（生成带 OG 预览的分享链接）。**P0**
- 约束：Frame 必须至少挂载一项（叙事 / 资产 / 交易想法 / 证据 / 时间窗 / 验证点），否则不可发布。**P0**
- Frame 自动导回其所属 Room，并纳入 Room 的 Signals 与排序。**P0**

**关键验收**
- 不存在"散帖"：无挂载的 Frame 无法发布。
- 分享链接落地为对应 Room，且预览卡含核心判断。

### E4 — /trade 模拟验证

**目标**：把理解推进到"愿意验证"，产出可结算的判断样本。**这是认知记忆的来源。**

**用户故事**
- 作为已看懂叙事的用户，我想用一次模拟仓位声明我的方向、失效点和时间窗，以便事后被客观结算、检验我的判断质量。

**需求**
- 建立 Paper Trade：方向（Long / Short / Uncertain）、标的、入场参考价、论点、**失效点（invalidation）**、**时间窗**、信心等级。**P0**
- Trade 与 Frame / Room 绑定。**P0**
- 追踪态展示：Emerging / Moving / Leading 三态 + 价格线 + 验证点。**P0**
- 自动结算：命中目标 / 触发失效点 / 时间窗到期 → 生成不可变 Settlement（见 §7.2）。**P0**
- 复盘：结算后生成可回看的判断复盘（对 / 错 / 校准度）。**P1**
- 组合视图 `/portfolio`：用户全部 Trade 与结算记忆的聚合。**P1**

**关键验收**
- `/trade` 全程不触及实盘下单，且 UI 明确标注"模拟 / 非投资建议"。
- 每个 Trade 必须含失效点与时间窗——无此二者不可建立（保证可结算）。

### E5 — 质量与事实底座（AI 供给管道）

**目标**：为 /bet、Room、/frame、/trade 提供可信度。慢一点，也要让每条判断有出处。

**需求**
- AI 叙事供给管道：抓取（新闻 / 价格变化 / 链上 / 用户线索）→ LLM 生成叙事假设 → 来源核验 → 判断框架 → 讨论素材。**P0**
- 质量门槛：清晰结论 + 来源 + 资产机制三者齐全才 published。**P0**
- 输出风格规范：bottom line + 容易被过度解读处 + 资产影响（见 §7.1 示例）。**P0**
- 缺失证据审查：标注"判断尚缺哪类证据"。**P1**
- 人工审核后台（可见内容抽检 / 下架）。**P1**

**关键验收**
- 抽检任意 published Cue：可追溯到来源，且判断与来源一致。

### E6 — 结算、信誉与记忆回流

**目标**：把分散的判断结果累积为可信的信誉与更好的排序。

**需求**
- 不可变结算事件日志（append-only）。**P0**
- 信誉计算（见 §7.3）：方向准确率、校准度、early-spotter、Frame 传播力。**P1**
- 排序回流：信誉与结算样本反哺 /bet 与 Room 内 Frame 排序。**P1**
- 用户认知档案：个人的结算记忆与信誉看板。**P1**

**关键验收**
- 任一结算记录不可被事后篡改（仅追加修正记录）。

### E7 — Agents / Feedback（后续）

**目标**：用 Agent 观察与用户反馈持续强化叙事供给与排序。

**需求**
- Agent 观察源接入叙事供给。**P2**
- 用户反馈（有用 / 误导 / 缺证据）回流排序信号。**P2**

### 横切需求（贯穿各 Epic）

- 账户与认证（注册 / 登录 / 个人档案）。**P0**
- 分享与 SEO（Room / Frame 的 OG 预览、可索引、快首屏）。**P0**
- 通知（Watch 的资产 / Room 有价格反馈或验证点时提醒）。**P1**
- 移动端（与 web 共享逻辑，独立 UI；见 tech-stack §5）。**P1**

## 7. 关键机制深入

> 这一节是产品"难且值钱"的核心，决定护城河。

### 7.1 AI 叙事供给管道（/bet 的命脉）

冷启动不靠用户先发内容，而靠 AI 持续供给。管道为常驻后台流程（非请求-响应）：

```
① 信号源：新闻、价格异动、链上事件、用户线索、（后续）Agent 观察
② 叙事假设：LLM 综合为"一句话判断 + 候选资产 + 时间窗"
③ 来源核验：拉取官方 / 二级 / 链上来源，核对判断与来源一致性
④ 判断框架：生成 bottom line + 容易被过度解读处 + 资产机制
⑤ 质量门槛：判断 / 来源 / 资产机制 三者齐全 → published；否则 rejected
⑥ 落地：published Cue 开启或并入一个 Narrative Room
```

> **AI 边界原则**：①（信号源）是**确定性工程抓取**，从受控数据源入库——**不是让 AI 联网搜索**。② 起才用 AI，且只对已入库的受控事件做综合。AI 要检索时，查的是我们自己的事件库（pgvector），不是公网。这是信任原则（每条判断可溯源）的前提。

**输出风格规范（示例）**：
> *Bottom line: category-positive, asset-multiple-negative. 标题容易被过度解读；品类被验证 ≠ 特定 venue 自动受益。*
> 同一份产出复用为：/bet 卡片文案、Room 讨论提示、Frame 选题、/trade 验证点。

成本分级：抽取/分类用 Haiku，叙事生成用 Sonnet，复杂核验用 Opus（见 tech-stack §4）。

### 7.2 记分与结算模型（/trade 的灵魂，见 §11-A）

> **推荐方案：模拟盘外壳 + 校准式（calibration）记分内核。**
> 即——界面上是 Paper Long / Short / 仓位，但**回流信誉的不是盈亏金额，而是判断质量**。

一个 Trade 的可结算要素：
- **方向**：Long / Short / Uncertain
- **失效点（invalidation）**：什么条件成立则判断作废（必填）
- **时间窗**：到期时间（必填）
- **信心等级**：用户对该判断的主观信心（用于校准）

**结算判定**（到期或触发时，按价格 / 事件快照）：
- 命中论点方向 → 正确
- 触发失效点 → 错误
- 时间窗到期未达成也未失效 → 未兑现（按论点性质判定 部分 / 无效）

**记分维度**（累积为信誉）：
- 方向正确性（hit rate）
- **校准度**：高信心是否对应高命中（Brier-style，奖励"诚实标注信心"）
- 时效：是否在失效点前兑现
- 不奖励"赌一把大的"——这是与传统模拟盘排行榜的根本区别

> 备选方案（P&L 模拟盘）见 §11-A，会长出完全不同的产品，需先拍板。

### 7.3 信誉系统

- 信誉来自**结算样本**，而非发帖量或点赞。
- 维度：方向准确率、校准度、**early-spotter**（在 Emerging 阶段就进入并判断正确）、Frame 传播力（带回流量且关联判断兑现）。
- 用途：信誉加权叙事 / Frame 排序；高信誉用户的判断在 Room Signals 中权重更高。
- 防刷：仅 settled 样本计分；失效点 + 时间窗强制，避免"永不结算"的挂单刷分。

### 7.4 排序与分发

- `/bet` 排序信号：时新性、来源质量、价格响应（Moving）、判断流动性（站队/Frame 数）、结算反馈。
- Room 内 Frame 排序：信誉加权 + 关联判断兑现 + 传播数据。
- 原则：**质量门槛是硬约束，排序是软优化**——不过门槛的内容再热也不可见。

## 8. 信任与合规原则

### 8.1 可见内容五原则（源自 deck 信任页）

| 原则 | 要求 | 级别 |
|---|---|---|
| 来源证据 | 重要判断必须可见来源，不靠模型语气 | 必须 |
| 清晰结论 | 给出可读 bottom line，并承认标题易被过度解读处 | 必须 |
| 资产机制 | 资产连接需说清：什么变量变化、为何影响定价 | 必须 |
| 结构化判断 | 站队 / 关注 / 时间窗 / 风险 / Frame / 关联交易可聚合 | 必须 |
| 结算记忆 | 模拟结果 / 价格 / 时间窗 / 传播结果回流信誉与排序 | 强化 |

### 8.2 合规底线（金融产品必须）

- 全站显著免责：**不构成投资建议**；叙事为信息与认知工具。
- `/trade` 全程标注**模拟 / 非实盘**，不涉及真实资金与撮合。
- 数据来源标注与版权合规（行情 / 新闻源授权）。
- 用户生成内容审核机制（误导 / 操纵市场内容下架）。

### 9.1 北极星

> **可结算认知样本的数量 × 质量** —— 即"用户把判断推进到可验证、并被结算"的规模。它同时代表参与深度与产品独有价值。

| 环节 | 指标 |

## 10. 发布路线图与 MVP 范围

> 阶段以**里程碑/验证**为门槛，时间为参考（源自 deck，不作硬承诺）。

- 范围：Trade 仓位叙事绑定、模拟结算、信誉回流、用户复盘、排序反哺、`/portfolio`。
- 门槛：结算记忆累积并可见地改善排序。

## 11. 开放决策点（需拍板）

> 以下决策会改变产品形态。文档已采用**推荐方案**书写；此处集中列出供你确认或推翻。

### A. /trade 记分内核 ★最高优先
- **推荐**：模拟盘外壳 + **校准式记分**（奖励判断准 + 诚实标信心，不奖励盈亏金额）。
- 备选：纯 P&L 模拟盘（奖励收益率）。
- 影响：决定信誉系统、排行、整个产品的价值观。**选错要重做**，请优先拍板。

### B. MVP 首发标的
- **推荐**：**Crypto 优先**（24/7 结算、行情免费、叙事驱动、结算最简单）；asset 模型支持多类别，股票 / 宏观在阶段三后开。
- 备选：首发即跨 crypto + 股票（结算复杂度高一档，需付费行情 + 交易时段处理）。

### C. 商业化模式
- **推荐**：MVP 不做商业化；远期方向为**高级研究 / 数据订阅**（不做佣金交易，避免牌照）。
- 待定：是否引入机构 / 专业版。

### D. 用户优先级
- **推荐**：首发 P-B（Crypto native）+ 好奇的 P-A；P-C 走分享入口。
- 待定：是否第一天就为 P-C 做主动获取。

### E. "信心等级"的量化形式
- 待定：离散档位（低/中/高）vs 概率百分比。影响校准记分的精度与易用性。
